# Requirements Document: Redux Setup

## Introduction

This document specifies the requirements for implementing a generic, reusable Redux Toolkit setup for a Next.js 16 App Router project with TypeScript. The system provides centralized state management following Next.js 16's server/client component model, where Redux is isolated to client components. The setup includes store configuration, provider wrapper, typed hooks, and patterns for creating feature slices.

## Glossary

- **Store**: The Redux store instance that holds the complete state tree of the application
- **StoreProvider**: A client component that wraps the component tree and provides Redux context
- **RootState**: The TypeScript type representing the complete application state shape
- **AppDispatch**: The TypeScript type for the store's dispatch function
- **Slice**: A collection of Redux reducer logic and actions for a single feature
- **Selector**: A function that extracts specific data from the Redux state
- **Thunk**: An async action creator that can dispatch multiple actions
- **Reducer**: A pure function that takes current state and an action, and returns new state
- **Client_Component**: A React component marked with 'use client' directive that runs in the browser
- **Server_Component**: A React component that runs on the server (default in Next.js App Router)

## Requirements

### Requirement 1: Store Configuration

**User Story:** As a developer, I want a centralized store configuration, so that I can manage all Redux state in one place with proper TypeScript support.

#### Acceptance Criteria

1. THE Store SHALL combine all feature slice reducers into a root reducer
2. THE Store SHALL export TypeScript types for RootState, AppDispatch, and AppStore
3. THE Store SHALL provide a factory function that creates a new store instance
4. THE Store SHALL integrate Redux DevTools in development mode
5. THE Store SHALL configure default middleware with serializable state checking

### Requirement 2: Store Provider Integration

**User Story:** As a developer, I want a provider component that integrates Redux with Next.js App Router, so that all client components can access the store.

#### Acceptance Criteria

1. THE StoreProvider SHALL be marked as a client component with 'use client' directive
2. WHEN StoreProvider mounts, THE StoreProvider SHALL create exactly one store instance per render tree
3. THE StoreProvider SHALL wrap children with Redux Provider component
4. THE StoreProvider SHALL accept children as a prop and render them within the provider context
5. WHEN StoreProvider is used in root layout, THE StoreProvider SHALL make store available to all descendant components

### Requirement 3: Typed Redux Hooks

**User Story:** As a developer, I want pre-typed Redux hooks, so that I get automatic TypeScript inference when accessing state and dispatch.

#### Acceptance Criteria

1. THE useAppDispatch hook SHALL return a dispatch function typed as AppDispatch
2. THE useAppSelector hook SHALL accept a selector function and return the selected state with correct TypeScript type
3. THE useAppSelector hook SHALL support optional equality function for custom comparison
4. THE useAppStore hook SHALL return direct access to the store instance
5. WHEN a component uses typed hooks, THE component SHALL receive compile-time type checking for state access and action dispatch

### Requirement 4: Feature Slice Creation

**User Story:** As a developer, I want a consistent pattern for creating feature slices, so that I can add new state features following best practices.

#### Acceptance Criteria

1. THE Slice SHALL define an initial state with a TypeScript interface
2. THE Slice SHALL implement reducers as pure functions that do not mutate state
3. THE Slice SHALL export action creators automatically generated by Redux Toolkit
4. THE Slice SHALL export the reducer function for store configuration
5. WHERE async operations are needed, THE Slice SHALL use createAsyncThunk for side effects

### Requirement 5: State Serializability

**User Story:** As a developer, I want all state to be serializable, so that Redux DevTools work correctly and state can be persisted.

#### Acceptance Criteria

1. THE Store SHALL only accept serializable data in state (no functions, class instances, or circular references)
2. WHEN non-serializable data is detected in development, THE Store SHALL log a warning
3. THE Reducer SHALL produce state that can be serialized to JSON and deserialized without data loss
4. THE Slice initial state SHALL contain only serializable values

### Requirement 6: Async Thunk State Management

**User Story:** As a developer, I want predictable async operation handling, so that loading states and errors are managed consistently.

#### Acceptance Criteria

1. WHEN an async thunk is dispatched, THE Store SHALL set loading state to true
2. WHEN an async thunk succeeds, THE Store SHALL set loading to false, store the result data, and clear any error
3. WHEN an async thunk fails, THE Store SHALL set loading to false, store the error message, and preserve existing data
4. THE async thunk SHALL follow the state machine: idle → pending → fulfilled/rejected
5. THE async thunk SHALL accept serializable payload and return serializable result

### Requirement 7: Client Component Boundary

**User Story:** As a developer, I want clear separation between server and client components, so that Redux only runs in the browser where it's needed.

#### Acceptance Criteria

1. WHEN a component uses useAppSelector or useAppDispatch, THE component SHALL be marked with 'use client' directive
2. THE StoreProvider SHALL be a client component
3. THE Server_Component SHALL not directly use Redux hooks
4. WHERE server components need state data, THE data SHALL be passed as props from client components
5. THE Store SHALL not be instantiated during server-side rendering

### Requirement 8: Action Type Uniqueness

**User Story:** As a developer, I want unique action types across all slices, so that actions don't conflict or trigger unintended reducers.

#### Acceptance Criteria

1. THE Slice SHALL generate action types prefixed with the slice name
2. WHEN two slices are created, THE action types SHALL be unique across both slices
3. THE Store SHALL handle each action type with only its intended reducer
4. WHEN an action is dispatched, THE Store SHALL route it to the correct slice reducer

### Requirement 9: Selector Purity and Consistency

**User Story:** As a developer, I want selectors to be pure functions, so that they return consistent results and enable proper memoization.

#### Acceptance Criteria

1. THE Selector SHALL be a pure function that does not modify state
2. WHEN called with the same state, THE Selector SHALL return the same result
3. THE Selector SHALL not create new object or array references unless the underlying data changes
4. WHERE derived state is needed, THE Selector SHALL use memoization to prevent unnecessary recalculations
5. THE useAppSelector hook SHALL only trigger re-renders when selected state changes

### Requirement 10: Error Handling and Recovery

**User Story:** As a developer, I want clear error messages and recovery paths, so that I can quickly diagnose and fix Redux integration issues.

#### Acceptance Criteria

1. WHEN a component uses Redux hooks outside StoreProvider, THE system SHALL throw an error with message "could not find react-redux context value"
2. WHEN non-serializable state is detected, THE middleware SHALL log a warning in development mode
3. WHEN an async thunk fails, THE Store SHALL capture the error message and store it in state
4. WHEN a selector causes performance issues, THE system SHALL provide guidance on using memoization
5. WHEN Redux hooks are used in a server component, THE system SHALL produce a build or runtime error

### Requirement 11: TypeScript Type Safety

**User Story:** As a developer, I want compile-time type checking for all Redux operations, so that I catch errors before runtime.

#### Acceptance Criteria

1. THE Store configuration SHALL export RootState type derived from all slice states
2. THE Store configuration SHALL export AppDispatch type including thunk support
3. WHEN dispatching an action, THE TypeScript compiler SHALL validate the action type and payload
4. WHEN selecting state, THE TypeScript compiler SHALL infer the correct return type
5. THE Slice SHALL define state interface and action payload types

### Requirement 12: Development Tools Integration

**User Story:** As a developer, I want Redux DevTools integration, so that I can inspect state changes and debug issues during development.

#### Acceptance Criteria

1. WHEN running in development mode, THE Store SHALL enable Redux DevTools extension
2. WHEN running in production mode, THE Store SHALL disable Redux DevTools
3. THE DevTools SHALL display all dispatched actions with their payloads
4. THE DevTools SHALL show state before and after each action
5. THE DevTools SHALL support time-travel debugging in development
